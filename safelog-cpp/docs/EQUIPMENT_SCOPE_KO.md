# 산업 설비 점검으로 확장하는 SafeLog

## 서비스 주제

스마트폰으로 산업 설비의 외관을 촬영하고, AI가 사진에 보이는 손상·결함 후보를 표시하면 점검자가 확인·조치·재점검 이력을 남기는 안전점검 보조 앱이다. 컨베이어 벨트와 전기 설비를 우선 대상으로 하고, 건물 표면 점검은 별도 기능으로 유지한다.

## 사진으로 점검할 항목과 추가 측정 항목

| 설비 | 사진 점검 후보 | 별도 측정·사람 확인 |
|---|---|---|
| 컨베이어 벨트 | 균열·찢어짐의 위치와 외관 변화 | 정렬·장력·회전 상태·진동·모터 온도·정지 여부 |
| 전기 설비·회로기판 | 등록한 기판 유형의 외관 결함 후보 | 전류·절연·과열·실제 회로 동작 |
| 배선·고정 부품·보호 덮개 | 피복 손상·누락·외관 변형 등을 후속 데이터로 추가 | 체결 상태·내부 손상·안전 기능 동작 |

사진에서 이상을 찾지 못한 결과만으로 정상 가동이나 안전을 확정하지 않는다. 사진 분석 결과와 실제 고장 점검 결과를 각각 기록한다.

## 앱에 들어갈 흐름

1. **설비 등록:** 설비 이름·번호·종류·위치와 점검 주기를 등록한다.
2. **사진·점검 항목 입력:** 설비 사진, 점검 의견, 필요한 측정값을 넣는다.
3. **AI 외관 검토:** 손상 후보와 위치 표시를 보고 점검자가 채택·수정·거절한다.
4. **고장 점검 기록:** 가동 상태·측정값·확인 결과를 점검자가 기록한다.
5. **조치·재점검:** 담당자와 조치 내용을 남기고 조치 후 사진을 비교한다.
6. **보고서·이력:** 설비별 점검 결과, AI 제안과 사람의 최종 확인, 조치 사진을 보고서로 보관한다.

## 네 역할이 맞출 내용

| 역할 | 설비 전환에 맞춘 작업 |
|---|---|
| 1 · 촬영·검토 UI | 설비 종류 선택, 종류에 맞는 촬영 안내, 결함 후보·위치 표시, 점검자 확인 화면 |
| 2 · 로그인·DB·이력 | 설비 ID·종류·점검 항목·측정값·사람 확인·AI 버전·조치 전후 사진 저장 |
| 3 · AI 엔진 | 실제 설비 데이터 수집·정답 검증, 종류별 모델 학습·오탐 미탐 평가, 결과·모델 버전 전달 |
| 4 · 앱·조치·보고서 | 설비 등록과 점검 흐름 연결, 담당자 조치·재점검, 설비별 보고서와 앱 패키징 |

## 2026-10-12 추가 학습과 연결

컨베이어 원본1,071장을 추가해 학습1,397장/19구간·검증353장/4구간으로 확대했고 실제40epoch를 완료했다. 같은127장 미탐11.02%→5.51%, 손상 위치 IoU41.28%→44.70%다. 작은 균열 위치 IoU는 악화했고 정상 사진 오탐은 산정 불가다. 이 결과는 연구 후보이며5% 미만 달성으로 해석하지 않는다.

별도 로컬 컨베이어 API에서 실제 CPU 사진 분석과 heatmap 반환을 검증했다. [역할4 연결 설명서](EQUIPMENT_API_HANDOFF_KO.md)에 요청·응답·Qt/C++ 예제·DB 저장 필드를 기록했다. 기존 앱 기본 모델을 자동 교체하지 않았다.

새 철광석 컨베이어 이물질 원본6.23GB를 확보하고 작성자 SHA를 확인했다. 선별 사진18,933장의 정상은 이물질 없음이며 균열 없는 벨트 정답과 다르다. 촬영명 분리·중복 검사를 마친 뒤 별도 `conveyor_foreign_object` 모델로 학습할 자료이며 아직 학습하지 않았다.

## 역할 3의 첫 데이터와 모델

- **회로기판:** Amazon VisA의 PCB1~4만 사용한다. 식품·생활용품 사진은 설비 정답으로 학습하지 않는다. 네 유형의 정상 사진으로 각각20epoch 실제 학습한 학생·교사 이상 탐지 모델을 제공한다. 다른 종류의 기판·전체 설비 사진에 그대로 적용되는 범용 고장 모델은 아니다.
- **컨베이어:** BeltCrack 공식 V1 자료를 사용한다. 압축명14ks와 실제 내용의 개수·주석 형식에 차이가 있어, 실제9,645장의 파일 구성과 LabelMe `crack` 주석을 기준으로 검증한다. 작성자 TRAIN23개·VAL10개·TEST9개 촬영 구간의 분리를 유지한다. 처음에는 각 TRAIN/VAL 구간에서 최대32개의 정답 포함 프레임을 일정 간격으로 선택한다. 공개 원본 주석의 `imageData`와 실제 polygon/rectangle 정답으로 학습한다.
- 제공처429 요청 제한으로1,031장 계획 중 이미 완전한 원본이 확보된679장(학습552/19구간·검증127/4구간)부터 실제40epoch 학습했다. 사진 미탐11.02%·모델 좌표 IoU41.28%다. 정상 벨트 사진이0장이므로 사진 오탐은 측정할 수 없다. 이후 정상 벨트 자료로 오탐 검증을 추가한다.
- 건물의 `concrete_crack` 모델·정답을 벨트 균열 모델로 옮겨 붙이지 않는다.

## 팀 연결 시 지킬 결과 구분

- 설비 종류와 분석 범위를 함께 넘긴다. 연구용 PCB 결과의 `equipment_category`는 `pcb1`~`pcb4`다.
- 벨트 손상의 클래스는 `belt_crack`이다. 건물 균열과 다른 클래스다.
- 회로기판의 특징 불일치 점수는 확률이 아니다. 벨트의 위치 확률 지도도 실제 고장 여부를 확정하는 값은 아니다.
- 외관 분석 결과, 실제 고장 확인 결과, 점검자 검토 결과를 별도 필드로 둔다.
- 현재 연구 CLI와 새 모델의 수치는 기존 앱 API에 자동 연결된 상태가 아니다. 역할4가 설비 선택 화면을 연결할 때 명시적으로 모델 종류와 출력 범위를 전달한다.
