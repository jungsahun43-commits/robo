# v66-v67 부식 상태 자료의 좌표·지문 감사

## 수행한 범위

Eric Bianchi·Matthew Hebdon, Virginia Tech v2, DOI **10.7294/16624663.v2**의 원본 440항목을 검사했다. 공식 데이터 조건은 CC0이며 논문 DOI **10.1061/(ASCE)CP.1943-5487.0001045**도 인용한다. 저장소 MIT는 코드 조건이며 기존 InsPLAD·Ostrava·다른 자료 조건은 그대로 유지한다. 원저자 저장소 고정 revision은 `f3d098b09784ac7e78b160906952e7bc79940fb1`이다.

`0f42d74`에 v66 조건을 먼저 push한 뒤 실제 픽셀을 계산했다. 원본/512 사본과 MPO 추가 프레임을 포함한 **882개 RGB 보기**, native/512 마스크 **440쌍**의 완료 지문을 남겼다. 440항목을 882장의 독립 자연 사진이나 독립 부품이라고 세지 않는다. 원본과 사본의 encoded SHA를 확인하고 원본 파일은 수정하거나 전체 확장하지 않았다.

기존 v57 그래프의 94개 연결과 v61 Ostrava 지문/연결을 재사용했다. 이전 v57 783항목과 Ostrava 105항목의 canonical group이 정확히 복원됐다. 새 보기의 서로 다른 현재 그룹에 대한 pHash 비교는 **5,292회**, 추가 정확/근접 연결은 **0개**였다. 이 수량은 가능한 모든 근접 쌍의 수가 아니다. RGB/pHash·EXIF는 물리 부품·촬영·현장 독립성의 증명이 아니다.

## 발견한 주석 대응 문제

- **422항목**은 native PNG와 독립적으로 그린 JSON 다각형 raster가 정확히 같지 않았다. 이 사실만으로 모든 주석이 틀렸다고 결론 내리지는 않는다. 생산 도구/버전 차이 등 원인은 아직 확정하지 않았다.
- **18항목**은 고정한 JSON 좌표/크기 조건에 맞지 않았다. 이 가운데 일부는 캔버스 밖 다각형이나 크기 대응 문제일 수 있다. 임의 이동·재축척으로 고치지 않았다.
- 원본 이미지와 native PNG 크기가 다른 **TRAIN 8항목**: 233/234/235/238/240/241/242/243. 예를 들어 233 이미지 4814×3441과 마스크 5184×3456은 같은 좌표라고 가정할 수 없다.
- TRAIN 258은 `.jpeg`라는 이름이지만 실제 **3프레임 MPO**다. 모든 프레임은 제외용 지문만 계산해 같은 항목에 연결했다. 첫 프레임이 마스크와 검증되어 대응한다고 주장하지 않는다.

원래 native PNG는 모두 P 모드였고 원저자 VOC 팔레트의 0/1/2/3 클래스 의미를 검사했다. Good/배경에는 미미한 부식도 포함되므로, 이를 이진 녹 부재 정답으로 사용하지 않는다. 원래 Fair/Poor/Severe 상태 라벨과 `__ignore__` 계약을 유지한다.

## 복구와 별도 진단

첫 실행은 TRAIN 233의 이미지/마스크 크기 assertion에서, 첫 복구는 TRAIN 258의 MPO 형식 assertion에서 정지했다. 두 실행의 실패 JSON·stdout/stderr·부분 지문을 보존했다. 완료된 194항목, 이후 221항목은 각각 SHA를 묶어 재해독 없이 재사용했다. `409ea61`, `416d67c`에 복구 조건을 먼저 push했다. 마지막 복구는 **실패한 연구의 제외용 목록만 완성**하며 원래 정확 일치·최소 표본·TEST 조건을 통과로 바꿀 수 없도록 고정했다.

최초 실패 전 완료하지 못한 항목의 RGB 2회·마스크 1회 해독도 완료 항목과 구분했다. v67 참조 진단의 TRAIN PNG 3회 재해독 역시 새 자연 사진이나 학습으로 세지 않는다.

v67은 `fd1ad40`에 먼저 조건을 push하고 **1,760파일의 헤더만** 검사했다. TEST 사진 내용은 보지 않았다. 고정 TRAIN 0/1/10 PNG만 참조 비교했다. 공식 LabelMe v3.16.7 정적 코드의 L 캔버스 방식과 기존 감사의 1비트 캔버스 방식은 세 항목에서 출력이 정확히 같았다. native PNG와의 차이도 각각 2,564/1,499/5,375픽셀로 동일했다. 따라서 이 세 항목에서 캔버스 모드만 바꾸어 문제를 해결할 근거는 없다. JSON 기록 버전은 4.5.2로, 참조 v3.16.7이 실제 생산 환경이었다고 주장하지 않는다. 외부 코드는 텍스트로만 읽었다.

## 현재 결론

**v66 직접 native PNG/원본 JPEG 계약은 실패로 보존한다.** 원본/마스크/JSON을 수정하지 않았으며, 새 encoder 특징·모델 점수·gradient·optimizer는 모두 **0회**다. 소스 RGB/마스크 접촉시트 등 이미지 내용의 시각 열람도 0회다. 따라서 이번 단계가 오탐·미탐을 줄였다고 설명할 수 없다. 새 API·CPU/GPU 패키지·C++·ZIP 검사도 0회다.

기존 앱 v16과 승인 v51 overlay 및 연구 v62는 보존한다. 다음은 `CORROSION_JSON_PAIR_V68_NEXT_KO.md`의 원저자 JSON 기반 정답 계약을 독립적으로 검증하는 자료 단계다. v66을 통과로 소급 변경하지 않는다.
