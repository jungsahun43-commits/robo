# v43 실제 지도학습 묶음 확보와 픽셀 이전 감사

사전 commit `556b6c7`의 다운로드 r1 조건으로 원저자 Mendeley V1에서 **지도학습 ZIP만 확보했다**. 전체 6.4GB나 object detection/unsupervised 묶음은 받지 않았다. 원본 outer ZIP의 해당 압축 payload 872,637,838바이트를 HTTP 206으로 읽고 원래 내부 ZIP 874,753,167바이트로 직접 스트리밍 복원했다. 원본 내부 CRC32 `47c40d0a`, 정확한 크기, 안전 경로와 하위 모든 파일 CRC를 확인했다. 별도 압축 payload 복사본은 만들지 않았다.

내부 ZIP 로컬 SHA256은 `562e33ca768aac532569f9976c534640327d082402c0efbf140d93c8638fb4a8`이다. 이것을 전체 배포 ZIP의 저자 SHA256과 혼동하지 않는다. 이용조건은 Mendeley V1 및 고정 author LICENSE의 CC BY-NC 3.0, 논문 DOI `10.1080/01431161.2023.2283900`, 데이터 DOI `10.17632/5n3fjgvfyz.1`을 유지한다.

## 원래 평가 예약과 라벨 의미

아카이브에는 영상 항목 11,525개와 평가 라벨 목록 5개가 있다. **11,525개의 새로운 독립 자연 사진이라는 뜻은 아니다.** TRAIN 파일 항목 5,108개, publisher VAL 6,417개다. 원래 VAL 전체를 **독립된 평가 용도 예약**으로 보존하며 내부 학습 검증이나 CAL로 가져오지 않는다. 아직 JPEG/PNG를 해독·시각 열람하거나 모델에 입력하지 않았다.

평가 목록 5개와 실제 VAL 파일이 전부 대응한다. 주의할 점은 vari-grip의 다중 클래스 번호가 `bird-nest=0, good=1, rust=2`라는 것이다. 숫자 1을 일괄 이상으로 해석하면 정상 라벨이 뒤집힌다. 폴더의 의미 이름으로 정상/이상을 구분했고 원래 숫자 라벨은 보존했다. TRAIN의 `normal/corrosão`와 평가의 `good/rust`는 upper-shackle의 정상/부식 이름 대응이다. 손상 위치 상자나 pixel mask는 제공된 과제가 아니다.

모든 파일명에서 날짜와 DJI 원본 frame proxy를 읽었다. 평가 원본 frame proxy 3,159개와 같은 TRAIN 크롭·변형은 모든 설비를 함께 고려해 미리 제외했다. frame proxy는 실제 부품/비행 독립성의 증명이 아니며 정확·근접 픽셀 감사는 아직 필요하다.

| 설비 | 남은 TRAIN 정상/이상 파일 항목 | 같은 frame 제외 정상/이상 | 평가 정상/이상 |
|---|---:|---:|---:|
| glass-insulator | 548 / 560 | 143 / 130 | 29 / 30 |
| lightning-rod-suspension | 345 / 310 | 3 / 0 | 231 / 20 |
| polymer-insulator-upper-shackle | 728 / 730 | 14 / 10 | 31 / 33 |
| vari-grip | 243 / 450 | 115 / 190 | 238 / 43 |
| yoke-suspension | 21 / 260 | 278 / 30 | 5,742 / 20 |

TRAIN에는 같은 기본 파일이 존재하면서 `_0`, `_1` 등의 이름이 붙은 항목이 2,403개 있다. 증강 후보의 실제 변환을 검수한 것은 아니며 이를 추가 자연 사진으로 세지 않는다. 같은 폴더의 실제 원본 이름이 존재할 때만 suffix를 거슬러 올라간 기본 이름 proxy 기준으로, 남은 이상 TRAIN은 glass 56/lightning-rod 31/upper-shackle 73/vari-grip 45/yoke 26개다. 서로 다른 물리 부품 수나 확정 자연 사진 수는 아니다.

## 다음 우선순위

**upper-shackle부터** 진행한다. 모델 점수가 아니라 파일/원본 frame 지원이 가장 큰 부식 클래스(이상 기본 이름 proxy 73개, 정상 728개)라는 자료 근거로 우선순위를 정했다. yoke 정상 TRAIN은 frame 제외 후 21개여서 정상 FIT/검증/CAL을 충분히 나누기 어렵다. 이 유형을 먼저 돌리거나 증강 파일 수로 표본을 부풀리지 않는다.

다음 v44는 픽셀/그룹 감사다. 사진을 해독하기 전에 다음 조건을 하나의 데이터 프로토콜로 고정하고 commit한다.

1. 원래 publisher VAL 6,417개를 계속 평가 예약으로 유지한다. 모든 해당 크롭/증강·같은 원본 frame·정확 RGB/8방향 pHash2 연결을 TRAIN에서 제외한다. 원래 정상 평가 파일 수의 불균형도 보존한다.
2. upper-shackle의 기본 원본 이름 후보만 학습 후보로 삼고 사전 증강 항목은 별도 기록/제외한다. 자연 손상 사진 수를 독립 검증 없이 확정하지 않는다. 다른 설비의 원래 평가와도 frame/픽셀 연결을 검사한다.
3. 기존 다운로드된 보존 TEST 8,855장에 MPDD2 흰색 TEST 140장을 더한 8,995장과 비교한다. MSDD의 예약 TEST는 픽셀 파일을 받지 않았으므로 비교했다고 세지 않는다.
4. 전역 연결 그룹을 만든 뒤 한 가지 결정적 FIT/내부 검증/CAL 배정·최소표본을 **모델 점수 전에** 고정한다. 정상 CAL은 최소20장, 독립성 proxy/클래스별 표본 부족은 실패로 남기고 조건을 낮추지 않는다.
5. 현재 ZIP 확장 합계는 877,786,725바이트지만 마무리 C: 여유는 약 2.13GB다. 전체 사진을 별도 파일로 한 번 더 풀지 않는다. 픽셀 감사는 ZIP에서 한 장씩 RAM으로 읽고, 실제 후보로 선택한 upper-shackle 원본/평가 파일만 필요할 때 별도 저장한다(현재 metadata 기준 최대 801+64항목). 원본과 실패/캐시를 지우지 않으며 공간과 임시량을 다시 계산한다. 새 대규모 dense cache나 full 부모 가중치 복사본을 만들지 않는다.
6. 픽셀 감사 후 고정 FIT 예시만 시각 확인하고, 과제/입력 범위에 맞는 한 공통 encoder의 분류 후보 하나를 별도 학습 조건으로 고정한다. 아직 학습 구조·회차·VAL 선택·CAL·채택 조건은 미확정이다.

영상별 가시적 상태 분류를 전체 현장 사진의 자동 손상 위치 추적·설비 내부 고장·전기 안전 판정으로 바꾸지 않는다. 새 후보의 사진 FP/FN이 조건을 통과하고 새 CPU/GPU·실제 C++/기존 alias·위치 출력 보존을 검사한 뒤에만 반영한다. 현재 모델/ZIP은 v16-r1이다.

이번 heartbeat의 새로운 encoder 특징/gradient/optimizer/사진 점수/API·C++·ZIP 검사는 모두 **0**이다. 데이터 확보·CRC 감사·metadata 분리는 실제 모델 학습과 구별한다. 기존 Python 704개 SHA와 보호 315,334개 파일 크기/수정시각 보존도 확인했으며 보호 원본 전체 SHA를 모두 재계산한 것은 아니다.
