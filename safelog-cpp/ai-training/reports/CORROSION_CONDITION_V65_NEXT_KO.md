# v64-v65 실제 부식 상태 주석 자료 확보와 다음 감사

## 확보한 원배포 자료

Eric Bianchi·Matthew Hebdon의 [Virginia Tech v2 자료](https://data.lib.vt.edu/articles/dataset/Corrosion_Condition_State_Semantic_Segmentation_Dataset/16624663/2), DOI 10.7294/16624663.v2를 원저자 저장소가 직접 연결한다. 대학/Figshare 공식 메타데이터의 **데이터 조건은 CC0**이며 저장소 코드의 MIT와 구별한다. 요청된 데이터와 논문 DOI 10.1061/(ASCE)CP.1943-5487.0001045를 함께 인용하고 저자·출처·버전·변경 내역을 남긴다. 다른 자료의 이용 조건은 바꾸지 않는다.

원본 ZIP 333,388,620바이트와 지침 PDF·README RTF를 받았다. 세 파일 모두 배포자 MD5와 일치했고 ZIP 전체 CRC, 안전 경로, 2,201개 파일의 encoded SHA를 검사했다. 원본 ZIP의 로컬 SHA256은 `45f0ec8b26f1c09d707f3010af359a28e0985d385d2bf6d98b5d4dd308e9dbe5`다. 원본 ZIP·코드·노트북을 실행하거나 전체 확장하지 않았다.

## 예약과 현재 상태

`3affd13`에 조건·코드를 먼저 push했다. 원래 TRAIN 396항목, TEST 44항목 각각에 원본 JPEG·원본 PNG·원본 LabelMe JSON·512 이미지·512 마스크가 대응한다. 원래 TEST와 모든 사본 **44항목/220파일**의 명시 ID·SHA를 픽셀 해독 전에 예약했다.

`data/industrial-corrosion-condition-v65-metadata/reserved-original-and-resized-TEST-before-pixels.json` SHA256:
`d5325e1f9f9b2c96d9e7b1ffd2fd03d740e51799a5591d2ae78970176c5df396`.

원본/512 사본은 추가 자연 사진으로 세지 않는다. TRAIN과 TEST 양쪽의 숫자 파일명이 같다는 이유만으로 같은 물리 부품으로 묶지도 않는다. 아직 실제 픽셀 중복·촬영/교량 부품 묶음을 검사하지 않았으므로 440항목을 440독립 부품이라고 부를 수 없다.

고정된 첫 TRAIN JSON 3개(0/1/10)만 데이터로 읽었다. 실제 라벨 문자열은 `2_Fair_Steel_Corrosion`, `3_Poor_Steel_Corrosion`이며 polygon 정답이다. 원래 크기 메타데이터는 앞의 두 개가 1600×1200, 세 번째가 3648×2736이다. `imageData`는 있지만 base64 해독이나 이미지 열람은 하지 않았다. `imagePath`는 검증된 ZIP member 이외의 파일 접근에 사용하지 않는다. 현재 JSON의 group_id는 모두 None으로 물리 부품 ID의 증거가 아니다.

## 주석 의미의 중요한 차이

원저자 9쪽 PDF는 **텍스트만** 읽었으며 예시 이미지는 렌더링·열람하지 않았다. 원배포 README도 텍스트로만 확인했다. 별도 acquisition audit의 지침 미열람 표시는 다운로드 과정의 범위이며 후속 텍스트 확인은 `publisher-guidelines-text-only.json`에 기록했다.

이 자료의 Good에는 **부식이 없거나 미미한 경우**가 함께 들어간다. 도장 박리만 있는 영역과 부식 주변의 이물질은 별도 취급한다. 따라서 Good/배경을 기존 앱의 **모든 녹이 전혀 없는 정답**으로 바꿔서는 안 된다. Fair/Poor/Severe는 원저자의 사진 기반 상태 주석으로 유지하며 실제 부식 깊이·구조 안전 등급을 측정한 정답으로 확대하지 않는다.

원저자 코드의 BGR 표기를 실제 PNG의 RGB/팔레트/인덱스와 혼동하지 않는다. 아직 실제 PNG 픽셀 클래스는 검사하지 않았다. 모든 비검정 값을 임의로 이진 부식 정답으로 합치거나 Good을 자동 정상 라벨로 만들지 않는다.

## 다음 v66 자료 감사

1. 새로운 픽셀 계산 전에 코드·JSON에 해독, 원본/사본 연결, 실제 PNG와 LabelMe 좌표·클래스 확인, 외부 TEST 제외, 최종 분리와 최소표본을 한 번 고정하고 commit/push한다. 공식 원TEST 44항목·모든 사본은 보존한다.
2. 원본과 512 사본의 명시 대응을 연결하고 정확 RGB·회전/반전 pHash≤2, EXIF·문서화된 촬영/부품 정보를 함께 검사한다. 단순 숫자 파일명을 전체 자료의 같은 부품 ID로 쓰지 않는다.
3. 기존 보존 TEST 8,995장·InsPLAD 원평가 6,417장·새 TEST 6,481장 및 **Ostrava 원래 TEST 15장**을 지문 캐시로 재사용한다. 기존 v57 graph 94개 연결과 v61 결과를 재사용해 오래된 전체 해독·근접 감사를 반복하지 않는다. 원본/사본의 TEST 연결 개발 사진은 모두 제외한다.
4. 기존 개발 사진과 근접한 경우에는 기존 FIT/VAL/CAL 역할 하나를 유지하고 역할 충돌은 제외한다. Ostrava 60FIT/15VAL/15CAL/15TEST도 잠가 둔다. 다른 출처의 near duplicate를 다른 분리에 넣지 않는다.
5. 원래 TRAIN에서만 한 가지 FIT/검증/CAL 배정 규칙과 최소 표본을 고정한다. 미달이면 이동·최소조건 완화 없이 학습 전에 중단한다. 이미지/정답 내용을 보고 분리를 다시 고르지 않는다.
6. 실제 native PNG 크기·색/팔레트·JSON 라벨/좌표의 의미를 검증한다. 원본을 고치거나 잘못된 좌표를 추정해 복구하지 않는다. 처리 불가능한 경우의 중단/제외 정책도 사전에 정한다. 실제 정상·양성 수량은 이 검사 전에는 미확정이다.
7. 통과한 최종 FIT 첫 예시만 고정 QA한다. 아직 새 데이터의 사진/마스크/지침 예시 이미지 열람, encoder 특징·모델 점수·gradient·optimizer는 모두 0회다.

## 이후 학습의 범위

자료 준비와 의미 확인 후 **한 가지** 새 후보만 구성한다. 원래 상태 라벨을 유지하는 학습과, 명시된 부식 양성 영역만 이용하는 부분 주석 학습 중 어떤 정답 계약이 맞는지 먼저 정한다. 이진 녹 존재 모델에 자료를 함께 쓴다면 Good의 미미한 부식을 잘못된 음성 정답으로 강요하지 않는 valid/ignore 계약이 필요하다. 가능한 가설을 열거해 TEST에서 좋은 조합을 고르는 방식으로 진행하지 않는다.

기존 v16·승인 3작업과 연구용 v62를 보존하고 공통 인코더 하나에서만 새 분기를 학습한다. 구조·초기값·학습 대상·샘플링·회차/lr/손실·VAL 선택·CAL·채택 조건·캐시 용량·delta 검증을 사전 고정한 뒤 gradient를 계산한다. v63 실패한 AND/상위 비율/TEST 임계값을 반복 맞추지 않는다.

현재 이 추가 자료의 학습은 0회이며 성능 개선을 미리 주장하지 않는다. 교량 보고서 사진을 사용하더라도 과제 범위는 금속 표면 외관 주석의 학습이며 교량/댐 전체 안전 진단으로 확장하지 않는다. 파일·실패 후보·로그·캐시·가중치·ZIP을 삭제하지 않고 1GiB 이상 여유를 유지한다.
