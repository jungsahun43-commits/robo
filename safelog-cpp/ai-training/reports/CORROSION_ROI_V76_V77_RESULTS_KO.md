# v76 계약 실패와 v77 헤더 진단

v76은 `850333b`에 자료 조건을 사전 push했다. 고정 TEST는 rios/134,144,19,225,53,59,65이며 해당 원본·양쪽 주석·시각화 사본을 함께 예약했다. 원본이 없는 83번은 픽셀 계산 전에 제외했고 대체 시각화를 입력으로 쓰지 않았다.

첫 구현은 v75 metadata의 SHA 필드명 대소문자를 잘못 읽어 ROI/RGB 해독 전에 실패했다. `42f7633`에서 필드명만 복구한 뒤 첫 실제 ROI가 정수 사각형 조건을 위반해 중단했다. 두 실패와 초기 코드·빈 로그를 보존했다. RGB 픽셀 해독·모델 특징·학습은 모두 0이다. 설명문에 기댄 “각 5개·5×5 정수 patch” 계약은 **실패 상태**다.

v77은 `e6c442a`에 별도 헤더 전용 진단 조건을 push했다. 처음에는 예상 수 350 assertion이 출력 저장보다 먼저 있어 진단이 중단됐다. `67692d5`에서 실제 수량을 보존하도록 진단 출력만 복구했다. 헤더를 다시 읽은 횟수는 새 사진/학습으로 세지 않으며 v76 조건을 통과로 바꾸지 않았다.

- 원본 TIFF IFD 34개는 모두 단일 frame RGB이며 크기는 제각각이다. 사진 픽셀은 아직 해독하지 않았다.
- nested ZIP 70개의 전체 멤버 CRC·encoded SHA와 안전 경로를 검사했다. 실제 ROI 파일은 **703개**, 각 ZIP은 9~12개다. 원본 누락83의 주석도 이 수에 포함되며 학습 대상이 아니다.
- 전부 ImageJ version227/type1/옵션128의 **subpixel 사각형**이다. 소수 폭·높이는 대체로 20.0이며 작은 부동소수점 차이가 있다. type/shape/subtype/rounded 설정은 별도 기록했다.
- Mendeley 설명의 “각 5개·5×5”와 차이가 있다. 설명이 틀렸다고 단정하거나 배율4를 추정해 좌표를 고치지 않는다. 원파일과 차이를 보존한다.

고정 [ImageJ RoiDecoder](https://github.com/imagej/ImageJ/blob/4c4975d6df7cf89334e7bc7bb56c48f7b204f244/ij/io/RoiDecoder.java)와 [Roi](https://github.com/imagej/ImageJ/blob/4c4975d6df7cf89334e7bc7bb56c48f7b204f244/ij/gui/Roi.java)를 텍스트로 확인했다. 이 구현은 해당 subpixel flag에서 float x/y/폭/높이를 읽고, Roi 생성 시 x/y의 정수 변환과 폭/높이 ceil을 거친 픽셀 사각형을 사용한다. 외부 코드는 실행하지 않았다. 이것은 실제 제작 버전을 증명하는 것이 아니다.

다음 v78은 **제공된 실제 ROI 좌표를 사용하는 별도 정답 계약**이다. v76을 소급 통과시키거나 기존 원자료를 수정하지 않는다. TEST 예약과 사진/그룹/native/512 최소수는 그대로 두고, 제공된 모든 ROI를 사용하며 알 수 없는 형식·범위 밖 좌표·양음성 충돌은 중단한다. 단계별 unit은 정수 경계/unknown 3개, 별도 subpixel 변환/중첩 3개다. 아직 새 특징·gradient·optimizer는 0이며 독립 현장 검증도 없다.
