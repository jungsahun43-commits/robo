# 오류 검수와 작은 손상 보강 비교 계획

## 산업체 현장 점검이라는 목표

제품 목표는 **산업체 현장의 사진 점검·점검자 확인·보고서 생성**이다. 현재 AI 연구는 콘크리트 표면의 균열·박락을 보강하는 범위다. 기존 교량·댐 사진은 공장 벽·바닥·기둥에서도 볼 수 있는 공통 손상 형태를 학습하기 위한 보조 자료로 사용한다. 교량·댐이라는 자료 출처가 서비스의 대상 분야를 바꾸지는 않는다.

현재 시설 손상 학습 자료는 교량·댐 사진이 중심이며, 세 공개 자료의 검증 결과는 그 자료 안에서의 미탐·오탐률이다. **산업체 현장·공장 사진에서의 성능과 시설 안전 판정 능력은 검증하지 않았다.** 산업체 사용 환경에 가까운 자료와 독립 평가가 후속 보강의 우선 방향이며, 이번에는 새 산업체 자료의 수집·추가 학습을 실행하지 않는다.

이번 비교는 원본 사진 수·분석 항목을 유지하고, 기존 detail12,041행 중1,694행을 작은 손상 주변 맥락 crop으로 교체하는 대조군·보강군 한 쌍만 진행한다. 새 crop은 기존 TRAIN 사진에서 파생한 학습 행이며 새 독립 현장 사진이 아니다.

## 이번 작업의 근거

실제 추가24epoch 이후 세 출처의 균열·박락 최대 검증 미탐·오탐률은23.15%에서22.41%로0.74%p 줄었다. 어려운 학습 사진 반복 비중을 높인 시도는23.83%로 더 나빴다. 이 결과에 근거해 원인을 좁힌 자료 변경을 비교한다.

최신 DACL 검증에서 원본 주석 면적이 사진의1% 미만인 사례의 미탐은 균열28/93(30.1%), 박락37/105(35.2%)이다. 기존 자료에도 격자 확대12,041행과80×80 위치 감독이 있다. 같은 증강을 다시 추가하는 대신 실제 작은 주석 부위가 확대 화면에 들어오도록 일부 학습 crop을 교체한다. 작은 손상이 오류의 유일한 원인이라는 의미는 아니다.

## 1. 원본 정답을 보존한 검수 화면

완료된 원본19태그 보조 모델의 전체 TRAIN14,248행만 평가한다. 소스별 균열·박락 FP/FN과 TP/TN 비교 사진을 포함한 로컬 HTML을 만든다. 사진은 원본 경로로 참조하고 복제하거나 Git에 넣지 않는다. 모델 예측과 주석이 다른 이유를 작은 손상/다른 형태/촬영 상태/판단 불명으로 기록할 수 있다. 이 의견은 정답 수정이나 학습 반영과 별도이며 자동 반영하지 않는다.

## 2. 정답 기준과 보강 범위

- 원본7항목의 photo targets와 분할, 검증·시험 정답 유지.
- DACL의 Crack/ACrack를 앱의 균열 항목으로 묶은 현재 매핑 유지. Cavity만 공동 항목이고 Hollowareas를 합치지 않는다.
- 박락, Rockpocket, 풍화 등의 원본 태그가 함께 있다는 사실은 혼동 원인이나 주석 오류의 확정 근거가 아니다. 애매하면 검수 대기 의견으로 남긴다.
- [출처 논문의 클래스 설명·주석 한계](https://arxiv.org/html/2309.00460v1#A3)를 기준으로 검수한다. 원본 사진과 원래 주석을 보존하고 전문가 확인이 필요한 의견을 구분한다.
- 새 crop의 정답은 해당 crop 안의 출처 polygon/mask에서 다시 산출한다. 사진 전체의7종 양성 태그와19종 보조 태그를 crop에 그대로 부여하지 않는다.
- DamSegment에 없는5개 항목과 CODEBRIM 양성 위치는 미확인으로 유지한다. CODEBRIM은 새 ROI 대상에서 제외한다.
- 파생 crop은 새 독립 사진 수에 더하지 않는다. 데이터 사용 조건을 유지하고 로컬 `data/`, `runs/` 안에 둔다.

## 3. 같은 조건으로 한 쌍 비교

| 설정 | 대조군 | 보강군 |
|---|---|---|
| 초기 모델 | 기존 auxiliary frozen best.pt | 동일 SHA |
| 자료 | 기존 격자 detail | 작은 부위 주변 맥락 crop으로 일부 교체 |
| 교체되는 detail행 |교체 없음 |기존12,041행 중1,694행 교체 |
| 원본/전체 행수 |14,248 /26,289 |동일 |
| seed |51 |51 |
| 학습 |6epoch, patience6 |동일 |
| 입력/배치 |전체640 /8 |동일 |
| LR |backbone4e-5, head2.5e-4 |동일 |
| 출처 전체 추출 비중 |DACL .7 /Dam .1 /CODEBRIM .2 |동일 |
| epoch당 추출 |14,248, 복원 추출 |동일 |
| 평가 |원래 세 출처 전체 사진(grid1) |동일 |

대조군 이름 `facility-presence-target-roi-control`, 보강군 `facility-presence-target-small-region`이다. 자료 변경 하나의 효과를 우선 확인한다. 클래스별 양성/음성 추출 비율은 crop 정답의 재계산으로 달라질 수 있어 예상 비중과 실제 원본/crop·출처 추출 수를 함께 기록한다.

최대 미탐·오탐뿐 아니라 항목별 오탐 증가, 작은 부위 미탐과 원래 나머지5항목의 AP 변화를 확인한다. 검증 임계값은 동일한 규칙으로 후보별 선정하지만 원본 정답은 수정하지 않는다. 이번 비교는 미리 고정한 전체 사진만 평가하므로 확대 뷰를 반복 선택하지 않는다. 단일 seed 비교이므로 작은 차이를 확정적인 현장 개선으로 해석하지 않는다.

## 채택 기준

기존 앱 `facility-validation-v2`는 이 연구 비교로 자동 교체하지 않는다. 연구 후보가 좋더라도 전체7항목과 기존 YOLO 결합 규칙의 검증 및 앱 연결 평가가 별도로 필요하다. 원래5% 기준은 두 항목 각각의 세 출처별 FNR/FPR 모두 엄격히5% 미만이며, 검증 미달이면 보류 시험은 실행하지 않는다. 확인 대기한 사진을 맞았다고 세지 않는다.

## 팀 소개·발표에서 사용할 범위 설명

"산업체 현장 점검 기록을 돕는 앱이며, 콘크리트 표면의 균열·박락 AI는 공개 교량·댐 자료로 보강하고 있다. 공개 자료의 검증 결과를 기록했으며, 공장 현장의 정확도는 아직 별도로 측정하지 않았다. 최종 판단과 기록 확인은 점검자가 한다."

추후 자료 보강은 실제 사용할 산업체 환경과 손상 형태에 가까운 자료를 우선 검토한다. 자료 확보·라이선스 확인·현장과의 차이 검토 후 별도 계획으로 진행하며, 이번 비교에 새 자료가 들어간 것으로 기록하지 않는다.
