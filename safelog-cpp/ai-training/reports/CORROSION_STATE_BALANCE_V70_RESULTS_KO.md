## FIT 입력과 노출

276 FIT의 letterbox uint8 RGB/정답 바이트 SHA가 v69 입력과 정확히 같았다. native와 512 보기에서 상태를 포함한 사진 수는 모두 **276/271/207/66**으로 같아, 이 자료에서 Severe 사진이 resize 때문에 전부 사라진 것은 아니다. 512 정답의 상태별 픽셀은 40,630,445 / 7,047,620 / 4,987,703 / 1,330,264개다.

실제 7,680 replacement draw에서 상태별 사진 노출은 7,680 / 7,527 / 5,744 / 1,882회다. v69 손실의 `상태 존재 / 사진의 존재 상태 수` 계수를 합한 예산은 **2,748.67 / 2,677.50 / 1,780.67 / 473.17**이다. 이는 실제 gradient 크기·인과적 중요도를 측정한 값이 아니다. Severe의 사진 존재 빈도가 낮은 상태에서 같은 사진별 평균을 쓰면 전체 상태의 기여가 같아지지 않는다는 근거다.

## 한 가지 다음 후보

FIT의 그룹 균등 샘플링에서 `a_k = E[상태 k 존재 / 존재 상태 수]`를 구하고, **w_k=1/(4a_k)**를 기존 클래스별 CE+Dice 항에 곱한다. 사진 안에서 가중치를 다시 정규화하지 않아 FIT 기대 상태 예산이 각각 1/4이 되게 한다. 실제 gradient가 같아진다는 주장은 아니다.

FIT에서 고정된 네 가중치는 **0.6987341772151905 / 0.7156439066551432 / 1.0739299610894926 / 4.160804020100503**이다. 이 한 공식만 새 후보로 고정한다. 샘플링·구조·learning rate·TEST 임계값을 함께 탐색하지 않는다. v69의 **epoch0 초기 head와 FIT normalization 및 draw 바이트를 재사용**하며 선택6/마지막30으로 초기값을 사후 고르지 않는다. 같은 가중 목적을 학습과 내부 VAL 선택에 사용하므로 v69의 비가중 VAL 숫자와 직접 비교하지 않는다.

가설의 원인이 증명된 것은 아니며 실제 비교 학습에서 검증해야 한다. 새 후보의 실제 학습·평가는 별도 v71 사전 고정 프로토콜에 따르고 source/앱 조건은 완화하지 않는다.
