# v71 손실 예산 보정 비교 — 전체 후보 제외

`1898811`에 조건을 먼저 push했다. v70의 FIT·내부 VAL 진단에 따라 **하나의 FIT 가중 공식**만 적용했다. v69 epoch0 초기 head/FIT normalization과 입력·정답·draw 바이트를 그대로 사용했으며 샘플러·구조·학습률·TEST 임계값을 함께 바꾸지 않았다.

## 실제 학습과 선택

실제 **30epoch×64=1,920 optimizer**를 완료했다. FIT276/내부VAL60의 같은 사진을 다시 사용한 것이며 새 자연 사진을 추가한 것은 아니다. 가중 VAL 손실은 초기 **2.19720524 → 1.41026981**, 선택은 **epoch6/384업데이트**다. 이는 v69의 비가중 VAL 숫자와 직접 비교할 수 없다.

CAL60에서 고정 temperature1.0/argmax 정책을 저장하고 원TEST44를 한 번 평가했다. 마지막 가중치를 사후 승격하거나 TEST에 맞춰 가중치를 반복 변경하지 않았다.

Severe는 560,175/1,894,856픽셀을 맞혔지만 해당 상태 IoU는 9.29%다. Fair/Poor의 IoU는 각각29.39/28.73%로 내려갔다. 이것은 일부 희소 상태 학습이 늘었다는 근거이며 전체 성능 개선이나 원인 증명의 근거는 아니다. 전체 픽셀 정확도도81.10%다.

**macroIoU≥40%와 Fair 이상 픽셀 미탐≤20% 조건에 미달해 전체를 제외했다.** 실제 미탐20.24662067%를20%로 반올림해 통과시키지 않는다. Severe만 골라 반영하거나 같은 가중치·구조·임계값 탐색을 이어가지 않는다.

이 지표는 `Fair 이상` 대 `Good/최소 부식`의 픽셀 집계이며 모든 녹 대 무부식 또는 전체 사진 오탐·미탐이 아니다. 전체 정상 TEST사진이 없고 Severe 포함 사진도12개라 독립 현장 성능·0미탐 보장으로 확대하지 않는다. 새 앱 채택·기존 alias 교체·fresh CPU/GPU 조건부 검사·API/C++/ZIP 검사는 모두0회다. 기존 앱/역할4 전달물은 유지한다.

## 보존

v69/v71 epoch0의 head tensor/buffer를 별도로 비교해 모두 정확히 같음을 확인했다. 상태 SHA는 `9e01b76f4a21dcd4fd949b92056f37fd16319e52563bea2fd69595d62d1e2ec2`다. checkpoint의 VAL 메타데이터가 다르므로 파일 SHA가 같다는 뜻은 아니다. FIT/검증 입력·정답과 draw SHA도 정확히 같았다.

학습 runtime 오류0개다. 기존 v62 부모의 모든 tensor/buffer/metadata와 disk delta 복원 exact, 기존 Python **779파일 SHA**, 보호 **330,548파일 stat**, 실제 update1..1920을 확인했다. 모든 원본 전체 SHA를 재계산한 것은 아니다. 새 normalization 특징 계산은0회이며 기존 FIT 전용 초기 buffer를 그대로 읽었다.

실패 연구 파일 `runs/industrial-corrosion-state-balanced-v71/trained/final-delta.pt`:

- 파일 SHA256 `5a6a2a879fe04643e24685fce367c83a3728bf60cc9ed8de60471cd269ec43b8`
- 결합 tensor 상태 SHA256 `355b1b9983777bf52b854b3f73a94616c6212e800b628e0d8948000c0f8f52f3`

부모 v16이 필요한 차이본이며 단독 앱 모델이나 새 배포 API SHA가 아니다. v69/v71 실제 optimizer 합계는 **3,840회**, 추적한 이전 일부 연구와 합계 **57,040회**는 실패 포함 부분합이지 전체 역사 총량이 아니다. v70 진단은 optimizer0회다.
