# AI와 SQLite 통합 · 2026-11-23

기준은 `feature/mobile-storage-auth`의 `418024ee98b6f0ffe947098533506f777bff686c`다. 최신 DB·사진 보관·로컬 로그인 코드를 유지하면서 기존 고정 CPU 분석기를 연결했다. 모델 가중치·판정 기준·학습 자료 역할과 원래 평가 기록은 변경하지 않았다. 전체 AI 20항목과 기타 직접 검토를 제공하고 발표 선정은 볼스크루·시설 균열·컨베이어 이물질·RobustAD PCB·케이블이다.

## 저장과 복원

| 항목 | 저장 내용 |
|---|---|
| 점검 | AI 방식(`fixed-cpu`/`mock`/`manual`), 점검 분야, 원 점검자·담당자·상태 |
| 사진 | 앱 관리 경로, MIME, 제공된 width/height/fileSize. 저장 시 사본 바이트 보존 |
| AI 결과 | 모델·프롬프트, 설명·조치·분류·위험도, 제공된 점수, 출처·분야·후보 유무 |
| 추적 정보 | 모델 SHA와 서버가 제공한 입력 SHA, 원응답 JSON 문자열, PCB anomalyScore·threshold |
| 사람 판단 | Pending/Accepted/Edited/Rejected, 검토자, 조치 제출 회차, 조치·최종 확인 로그 |

후보 `false`와 점수 `0`도 그대로 보존한다. 값이 없는 confidence는 SQL NULL이며 앱에서는 없는 속성으로 복원한다. PCB anomalyScore를 확률로 바꾸지 않고 전후 비교의 고정 confidence 0.5도 사용자 확률로 만들지 않는다. 현재 비교 API가 제공하지 않는 입력 SHA를 추정해 추가하지 않는다. 전후 비교는 원응답·모델 식별값과 저장 사진·제출 회차에 연결한다.

HTTP 준비 상태·모델 SHA·응답 계약이 맞은 결과만 `WorkflowService`를 통해 저장한다. 오류는 후보 미검출이나 Mock 성공으로 바꾸지 않는다. AI 저장만으로 Verified가 되지 않으며 최종 확인은 원 점검자가 수행한다. PCB는 사진별 외관 분석만 연결하고 전후는 사람이 직접 비교한다.

## 기존 DB 보존

v1·v2 마이그레이션 문자열은 수정하지 않고 v3를 덧붙였다. 기존 계정·사진·조치 이력·검토 결정·AI JSON은 유지한다. AI 테이블은 하나의 마이그레이션 트랜잭션 안에서 재구성해 confidence NULL과 출처 필드를 지원한다. 중간 실패 시 DDL·데이터·user_version이 함께 롤백된다.

이전 `result_json`은 서버 원응답 여부가 명확하지 않아 기존 값 그대로 보존하고 `raw_json_present=0`으로 구분한다. 새 실제 원응답은 문자열을 그대로 저장하며 표시 값으로 재구성하지 않는다. 기존 사진·로그는 자연 키로 UPSERT해 다른 형식의 기존 ID를 강제로 교체하지 않는다. DB 저장 실패 시 메모리 스냅샷을 바꾸지 않고 이번에 만든 사진 사본만 정리한다.

관리자가 만든 새 담당자도 계정 저장소에서 조회해 배정한다. 현재 사용자 역할도 저장소와 대조한다. 보고서 이름 조회는 같은 프로필 목록을 사용하며 비밀번호 해시·salt는 UI 목록이나 보고서로 내보내지 않는다. 이번 변경은 기존 임시 비밀번호 규칙과 scrypt 비용 정책을 바꾸지 않는다.

## 플랫폼과 검증 범위

- Android/iOS: 기존 Expo SQLite 동기 어댑터와 앱 문서 폴더 사진 보관을 사용한다. 재시작하면 다시 로그인한다.
- 웹: 기존 메모리 저장을 유지해 새로고침 시 계정·점검이 초기화된다. SQLite·사진 영속 저장 완료로 표시하지 않는다.
- 기기별 로컬 DB이며 중앙 DB·서버 로그인·여러 기기 동기화는 포함하지 않는다.

자동 검사 103개로 기존 v1/v2 업그레이드, 실패 롤백, 전체 20개 HTTP 계약, 원응답·SHA·검토 결정·NULL/false/zero 저장과 DB 재개방, 신규 계정 업무 흐름을 확인했다. Node SQLite 드라이버는 앱과 같은 SQL을 사용하지만 실제 Expo 네이티브 드라이버와 동일한 장치 검증은 아니다.

실제 고정 CPU 모델·새 분석기·gateway로 9장(시설·컨베이어·PCB 기존 시연 6장, 볼스크루 FIT 2장·케이블 FIT 1장)을 호출해 원응답과 입력 SHA가 SQLite에 보관되는 것을 확인했다. 사진 사본의 바이트도 확인했다. 첫 리허설은 복원된 객체의 속성 순서를 JSON 문자열로 비교한 검사 코드 때문에 중단됐으며 원형은 보존했다. 9장 추론은 반복하지 않고 DB 사본에서 값과 원응답을 검증한 뒤, 아직 실행하지 않은 전후 비교와 사람 최종 확인을 이어갔다. 신규 담당자 배정 뒤 재개방, 조치 제출·실제 모델 전후 비교·Verified·보고서 이름과 사진 복원을 통과했다.

로컬 근거는 `outputs/safelog-mobile-db-ai-2026-11-23/`의 `tests-final.log`, `live/result.json`(최초 원형), `live-continuation/result.json`(후속 검증), 프로세스·모델 핀 영수증이다. 새 성능 벤치마크·실제 현장 조치·실기기 화면 조작·네이티브 PDF 공유 성공을 뜻하지 않는다. 새 학습·GPU·고정 TEST 열람은 0이다.

TypeScript·Expo lint와 Android·iOS·웹 번들 생성도 통과했다. 번들 생성은 네이티브 설치·기기 실행 검증과 구분한다. 전체 기록은 [검증 보고서](TEST_REPORT.md)의 2026-11-23 절에 있다.
