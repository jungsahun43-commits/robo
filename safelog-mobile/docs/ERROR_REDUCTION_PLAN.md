# 케이블·PCB 오탐·미탐 개선 작업 순서 · 2026-11-20

발표는 **볼스크루·시설 균열·컨베이어 이물질·RobustAD PCB·케이블 외관**으로 구성한다. 사용자가 현재 1·2·3번은 충분하다고 판단했으므로 해당 고정 전달본과 판정 기준을 유지한다. 새로운 후보를 검토해도 기존 부모를 교체하지 않으며 공통 모델 변경은 기존 분야의 보존 검증을 통과해야 한다.

현재 상태는 **발표 목록 교체·기존 집계 검토·작업 순서 준비 완료, 성능 개선 실험 미시작**이다. 학습 완료·성능 개선·새 자료 수용으로 표시하지 않는다.

## 개선 대상

| 우선순위 | 분야 | 현재 사진 오류 | 판단 |
|---|---|---|---|
| 1 | 케이블 외관 | 오탐 6/58 = 10.34%, 미탐 7/92 = 7.61% | 남은 오류가 가장 커서 먼저 보강할 대상. 양쪽 동시 개선은 새 검증으로 확인해야 함 |
| 2 | RobustAD PCB | 오탐 4/120 = 3.33%, 미탐 1/75 = 1.33% | 이미 오류 수가 적어 작은 차이를 개선으로 입증하기 어려움. 별도 기판·촬영 조건 검증 우선 |
| 유지 | 볼스크루·시설 균열·컨베이어 이물질 | [기존 집계](INSPECTION_CATALOG.md) 유지 | 이번 발표 준비에서 추가 튜닝 대상에 넣지 않음 |

케이블의 정상 평가 1장은 오탐률 약 1.72%p, 손상 1장은 미탐률 약 1.09%p에 해당한다. RobustAD의 손상 1장은 미탐률 약 1.33%p다. 분모가 작아 한두 건의 차이를 현장 성능 보장으로 해석하지 않는다. 사진 후보 판정과 정밀 위치 정확도는 별도이며 PCB의 현재 위치 출력은 정밀 결함 표시 기능으로 제공하지 않는다.

기존 케이블은 공통 분석부의 정상 FIT 178장과 정상 CAL 45장을 사용하는 정상 참조 방식이다. 과거 `정상 참조 CAL20` 후보는 미탐 2.17% 대신 오탐 39.66%로 모두 기준을 충족하지 못했다. [기존 정상 참조 실험 보고서](https://github.com/jungsahun43-commits/robo/blob/3776729e08a7b11511adcae303457fbd312d9dcf/safelog-cpp/ai-training/reports/EQUIPMENT_REFERENCE_RESULTS_KO.md)의 과거 결과로 보존하며 재실행하지 않는다. 해당 집계만으로 현재 오류의 촬영·손상 유형별 원인을 확정할 수 없다.

## 실행 순서

1. **발표 구성과 연결을 먼저 고정한다.** 앱의 선정 목록을 케이블로 바꾸고 전체 20항목은 유지한다. 볼스크루·케이블의 별도 시연 사진은 권리·원래 역할·파일 식별값을 확인한 자료만 사용해 모바일 연결을 리허설한다. 성공하는 사진만 고른 결과를 새 정확도 수치로 발표하지 않는다.
2. **케이블 개발 자료의 적격성과 오류 분류를 준비한다.** 기존 집계에는 세부 오류 유형이 없어 원인을 확정할 수 없다. 새 TRAIN/VAL 자료에서 부품 유형·크기·각도·초점·조명·배경·현재 손상 정답의 일관성을 확인할 계획을 먼저 정한다. 기존 고정 TEST의 실패 사진을 열어 개발 방향을 고르거나 학습으로 이동하지 않는다. 단순 촬영 안내는 입력 준비이며 측정된 성능 개선이 아니다.
3. **권리·정답·역할·촬영 그룹·예산 검증을 통과한 뒤 후보 하나를 준비한다.** 실제 제작자와 부모·제삼자 권리, 자연 RGB의 native 현재 손상 GT 및 명시 배경·unknown·좌표, 원TRAIN/TEST/VAL과 물리 촬영 group, 기존 source/held 전체 graph, 고정 최소, bytes/checksum, 모델·보관·전송 조건을 확인한다. 부족한 자료를 추정한 취득 코드나 빈 학습 packet으로 대체하지 않는다.
4. **정확한 코드·정책·예산과 평가 절차를 사전에 고정한다.** 필요한 구체 전송 승인, 일반 사전 push와 원격 확인을 마친 뒤 자료 감사 및 공통 encoder 후보 1개를 순차 학습한다. 원래 공통 부모와 정규화·호출 계약을 유지하고 별도 encoder를 임의로 추가하지 않는다. fresh CIM·lock·예산·보호 SHA 확인 전 job을 시작하지 않는다.
5. **VAL로 후보를 선택하고 CAL을 저장한 뒤 고정 TEST는 정해진 1회만 평가한다.** 오탐을 낮추면서 미탐을 늘린 결과를 양쪽 개선으로 부르지 않는다. 기존 TEST에 맞춘 임계값·구조·조건 탐색이나 닫힌 실패 후보 재실행을 하지 않는다. 기존 사진·그룹·오류율 최소와 분야별 회귀 제한을 완화하지 않는다. 통과 후보만 retention/runtime·CPU/GPU·실제 C++·기존 alias/PNG 검증을 거쳐 채택 대상으로 검토한다.
6. **PCB는 케이블 뒤에 별도 검증한다.** 현재 PCB 모델은 5유형이 한 학생 가중치를 공유하므로 RobustAD만의 개선이 다른 PCB에 회귀를 만들 수 있다. 우선 권리·역할·촬영 그룹이 확인된 별도 사진으로 적용 범위를 점검한다. 기존 TEST의 미탐 1장을 없애려고 기준을 조정하지 않는다.

## 역할별 준비물

| 담당 영역 | 준비할 것 | 완료 기준 |
|---|---|---|
| AI | 적격 개발 자료 목록, 현재 모델·부모 SHA, 사전 프로토콜·전체 예산, 오류 분류와 양쪽 오류율·회귀 보고서 | 자료·모델·평가·보존 gate 통과 전 학습 대기. 통과 뒤 실제 측정 결과로 판단 |
| 촬영·모바일 UI | 케이블 대상 유형·근접 사진 범위 안내, 분야 선택 보존, JPEG/PNG·크기 검사, 오류와 후보 미검출 구분 | 다른 분야로 잘못 전송하지 않고 원본·실제 응답을 보존. 자동 보정·크롭을 검증 없이 추가하지 않음 |
| 저장·피드백 | 사진의 원래 역할·촬영 그룹·출처, 모델/입력 식별값, AI 제안과 사람의 최종 결정을 별도 기록 | 사람의 수정 기록을 자동으로 학습 정답으로 승격하지 않음. 현재 앱의 메모리 저장 한계는 별도 개발 과제로 명시 |
| 업무·보고 | 사람 검토, 조치·재조치·최종 확인, 연구 지표와 해당 사진의 결과를 구분 | 임계값·점수를 UI에서 임의 변경하지 않음. 연결 검사·시연 성공·정확도 평가를 별도로 표시 |

임계값은 같은 점수를 어떤 후보 판정으로 바꿀지 결정한다. 한쪽 오류를 줄이면서 다른 쪽이 늘 수 있고, 검증 자료와 분리 없이 조정하면 과적합 위험이 있다. [scikit-learn 공식 임계값 문서](https://scikit-learn.org/stable/modules/classification_threshold.html)는 일반 원리 참고이며, 현재 고정 모델의 기준 변경 승인이나 해당 도구 도입을 뜻하지 않는다.

현재 집계의 원형 근거는 [전체 항목표](INSPECTION_CATALOG.md)의 선정 통합 전달본 `evaluation.json`과 [PCB 결과 보고서](https://github.com/jungsahun43-commits/robo/blob/3776729e08a7b11511adcae303457fbd312d9dcf/safelog-cpp/ai-training/reports/PCB_MULTISOURCE_RESULTS_KO.md)다. 과거 실제 취득·실패·epoch·cache·평가·GT 역할 graph·모델·앱·원형 기록을 보존한다. 이번 목록 교체로 새 학습·TEST 실행·삭제·원격 게시·반복 자동화를 시작하지 않는다.
